## 1. 로컬 기준값 (2026-09-15)

- 장비: Apple M4, Python 3.14, 워크트리 venv
- 경로: `problem_parser.parse_problems()` — OCR·AI 끔, 칠판 cutout 없음
- 입력: 실제 텍스트 PDF의 앞 3쪽(`fitz` `select`로 자름). 파일은 저장소에 넣지 않았다

| 입력 | 3쪽 파일 크기 | 전체 | 인식 | crop | 최대 RSS | 결과 |
|---|---|---|---|---|---|---|
| 2026학년도 수능 국어(언어와매체) 홀수형 | 2.89 MB | 1.70초 | 0.99초 | 0.55초 | 556 MB | 문항 1~9 + 지문 3개, 확인 필요 7개 |
| 2026학년도 9월 모평 국어(언어와매체) | 3.88 MB | 1.63초 | 0.95초 | 0.53초 | 556 MB | 문항 1~9 + 지문 2개, 확인 필요 7개 |

### 이 값에서 읽을 것

- **시간·메모리는 여유가 있다.** 스펙 기준(웜 p95 20초, RSS 1.6 GB)의 1/10, 1/3 수준이다. Vercel 1 vCPU가 M4 코어보다 2~3배 느려도 5초 안쪽이다.
- **파일 크기가 4 MB 상한에 가깝다.** 국어 시험지는 글꼴을 품고 있어 3쪽만 잘라도 2.9~3.9 MB다. 원본 16쪽 PDF는 그대로 올리면 4 MB를 넘는다. 사용자는 대개 원본 전체를 올리므로, Plan 2에서 다음 중 하나를 정해야 한다:
  - 브라우저에서 pdf.js 없이 자르기는 어렵다 → 서버가 앞 3쪽만 처리하려면 원본 전체를 받아야 하고, 그러면 4.5 MB 본문 상한에 걸린다
  - Supabase Storage 직접 업로드(스펙 §3 제외 항목)를 되살린다
  - 안내 문구로 "3쪽 이하 PDF"를 요구한다(체험 문턱이 높아진다)
- "확인 필요" 표시가 12문항 중 7개로 많다. 결과 화면이 경고로 뒤덮이지 않게 Plan 2에서 표시 기준을 정한다.
